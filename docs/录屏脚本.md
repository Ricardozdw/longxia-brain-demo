# 录屏脚本（约 4～5 分钟）

## 录屏前准备（5 分钟）
1. 腾讯会议：已登录、停在首页；设置里关闭「入会开启摄像头」「入会开启麦克风」。
2. 准备一个真实会议号用于演示「加入会议」：用手机腾讯会议开一个会议并保持在会中（演示时让 Mac 加入）。
3. 清理数据（可选）：停服务后运行 `npm run reset`，保留模拟历史数据让看板好看。
4. 双击 `启动龙虾脑.command`，浏览器打开 http://localhost:4320/admin。
5. 手机扫码打开龙虾脑页面。
6. 录屏方式：
   - Mac：`Cmd+Shift+5` 录制整个屏幕；
   - 手机画面：iPhone 用数据线连 Mac，打开 QuickTime →「新建影片录制」→ 摄像头选 iPhone，把手机画面放在 Mac 屏幕右侧，**手机和电脑同框录制**。

## 分镜
| 时间 | 画面 | 操作 | 旁白要点 |
|---|---|---|---|
| 0:00–0:20 | 后台看板 + 手机首页 | 无 | “龙虾脑：在手机上说一句话，让电脑替你把事做完。今天演示两个场景，以及异常处理和运营看板。” |
| 0:20–0:40 | 手机 | 指着顶部「已连接 MacBook」，展示欢迎语 | “它是一个对话式的个人 Agent：扫码绑定电脑后，像聊天一样说需求就行，顶部实时显示电脑状态。” |
| 0:40–1:30 | 手机 + Mac Chrome | 点「🎬 放个热门电影」 | “没指定片名时，从豆瓣热门榜实时挑片。执行过程只占一行状态（如『打开视频并播放 · 4/5』），不打扰对话；完成后 Agent 用一句话告诉结果并附电脑画面截图，想看细节可以展开执行过程。成功的标准是**检测到播放进度在增长**。” |
| 1:30–1:50 | 手机 | 点「📞 加入会议」（发送“加入腾讯会议，会议码1234”） | “题目里的 1234 不是有效会议号——腾讯会议号是 9 位。我们在理解阶段就拦截，告诉用户哪里错、怎么改，而不是让电脑去试错。” |
| 1:50–2:30 | 手机 + Mac 腾讯会议 | 直接回复真实 9 位会议号（只发数字） | “Agent 记得上下文：只回一串数字，它就知道是要加入这个会议。电脑自动唤起腾讯会议入会，检测到会中窗口后回复成功。” |
| 2:30–2:50 | 手机 | 再发「创建一个腾讯会议」 | “电脑已经在会议中，为避免打断，本次不执行，并提示先离会。” |
| 2:50–3:30 | 手机 + Mac | Mac 上离开会议 → 手机点「重试」 | “离会后重试，电脑一键开快速会议，**会议号自动发回手机**，可直接复制转发给同事。” |
| 3:25–3:30 | 手机 + Mac | 点结果下方「结束会议」，再发「关闭」 | “能开就能关：一键结束会议；只说『关闭』，Agent 会判断电脑上在做什么再关掉。” |
| 3:30–3:50 | 手机 | 发「帮我订一张去上海的机票」 | “不支持的事明确告诉用户，并给出能力清单——MVP 先把少数场景做到可靠。” |
| 3:50–4:10 | 终端 + 手机 | 在终端 Ctrl+C 停服务 → 手机显示离线（或只结束助手进程后再发任务） | “电脑离线时手机立即感知，任务不会石沉大海。” |
| 4:10–4:50 | 后台看板 | 依次指 KPI、趋势、漏斗、场景表现、失败原因、任务明细；切换「包含模拟历史数据」 | “每次任务都是结构化数据：端到端完成率、执行成功率、理解率、耗时、失败原因 Top，用来决定下一个迭代修什么。7 天数据是模拟的，可以一键排除，只看刚才真实操作的记录。” |
| 4:50–5:00 | 产品方案文档 | 翻到路线图 | “后续：打包客户端、云端中转、扩展到更多场景，最终做成技能平台。” |

## 录制小贴士
- 每个任务发出后停 1～2 秒，让观众看清步骤条的变化；
- 视频场景成功后，镜头切到 Mac 上全屏播放的预告片停留 2 秒；
- 若某一步失败，不必重录——这本身就是异常处理的演示，点「重试」即可。
